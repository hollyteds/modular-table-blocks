# Modular Table Blocks

WordPressのブロックエディターで「テーブル → 行 → セル → コンテンツ」を編集するプラグインです。行・列操作、見出し行、列幅、基本装飾、横スクロールに加え、M2としてセルの結合・分割と、結合を考慮した行・列の追加・削除を実装しています。M3として継承スタイルの選択UI、アクセシビリティ・互換性の検証、配布ZIPの作成手順を追加しました。

変更履歴とバージョン管理の運用は [CHANGELOG.md](CHANGELOG.md) に記載しています。現在の `0.1.0` を基準とし、今後の変更は `Unreleased` に記録します。

## セットアップ

対象はWordPress 6.6以上、PHP 7.4以上。開発にはNode.jsとnpm、ブラウザーテストにはDockerとPlaywright Chromium・Firefox・WebKitを使用します。依存ツールの推奨環境はNode.js 24.18以上・npm 11.16以上です。

```sh
npm install
npm run build
```

このディレクトリを `wp-content/plugins/modular-table-blocks` に配置し、WordPressのプラグイン画面で有効化します。配布に必要なのは `modular-table-blocks.php`、`includes/`、`build/`、`languages/` です。生成物は編集せず、`src/` を変更してビルドします。

専用のローカル検証環境：

```sh
npm run env:start
npx playwright install chromium firefox webkit
npm run test:e2e
npm run test:php
```

WordPress 6.6／PHP 7.4を http://localhost:8890 、PHPテスト環境をポート8891で起動します。ログインは `admin` / `password`。テストは専用環境に投稿を作成・公開し、権限別の検証用に投稿者ユーザー `mtb-reload-author` を作成します。本番サイトには向けないでください。

WordPress 7.1.3／PHP 8.3の互換性確認は別環境です。

```sh
npm run env:start:latest
npm run test:e2e:latest
npm run test:php:latest
```

こちらは http://localhost:8892 。テスト用認証情報は `WP_USERNAME`、`WP_PASSWORD` で変更できます。

## 使い方

1. 投稿に「Modular Table」を挿入します。
2. 行数と列数を1〜20で指定して「Create table」を押します。既定は3×3です。
3. セル内の段落・リスト・見出し・画像・ボタンを編集します。行・セルの選択にはリストビューも利用できます。
4. テーブルの設定でキャプション・見出し行・列幅・横スクロール、セルの設定で `td` / `th`、見出しの関連付け、水平・垂直揃えを指定します。
5. 文字色・文字サイズ・行間は標準の「スタイル」タブ、水平揃えは標準ツールバーで設定します。罫線とセル余白は「スタイル」タブの別々の標準パネルで設定します。余白は「サイズ」、罫線は「枠線と影」に相当するパネルで、影の設定はありません。背景色と表幅は「テーブルのスタイル」で指定します。未設定なら親またはサイトの設定を引き継ぎ、各項目の解除で継承へ戻せます。
6. 行またはセルを選択し、ブロックツールバーの「テーブルの構造」から行・列を操作します。挿入・複製・移動・削除の操作はツールバーに集約しています。テーブル選択時は末尾への行・列の追加ができます。設定サイドバーでは、必要な場合に操作できない理由やエラーを表示します。
7. 結合範囲の左上セルを選択し、同じツールバーの「セルを結合」から行数・列数を選びます。既存の結合セルは全体を範囲に含め、見出し行と本文の境界をまたがない長方形にします。「セルを分割」で1×1のセルへ戻せます。

結合時は範囲内のすべての内容を読み順で左上セルへ移し、左上セルの種類・見出しの関連付け・スタイルを使用します。他のセルの個別設定は引き継ぎません。分割時も内容は左上セルに残り、追加したセルは空になります。元の内容配置やセル設定へ戻すにはUndoを使用してください。

結合の内側に行・列を挿入すると結合幅を広げ、結合に重なる行・列を削除すると幅を縮めます。結合元の行を削除しても、結合が残る場合は内容を次の行へ移して保持します。縦結合に影響する行の移動・複製は拒否し、理由を表示します。

内容のある行・列の削除では確認画面を表示します。キャンセルで取り消せます。適用した構造操作は1回のUndoで元に戻り、Redoも可能です。確認中に表が変わった場合は削除を拒否します。初期作成は1〜20行・列、構造操作での上限は100行・50列です。

見出し行は位置に基づく設定で、先頭行を `thead` と `th scope="col"` で出力します。各セルに保存した `td` / `th` と `scope` は上書きしません。見出し行の解除で元の設定へ戻ります。行を移動した場合も、その時点の先頭行が見出しになります。

列幅は単位切り替えを内蔵した数値欄で指定し、「自動幅に戻す」で自動調整へ戻せます。指定時は0より大きい100%以下・4000px以下・250rem/em以下です。編集画面では入力用に各列の最小幅を8remとし、幅が足りなければテーブル内を横スクロールできます。セルと段落等の本文領域は列の幅を満たし、入力文字数によって縮まないようにしています。公開側の自動テーブルレイアウトと編集画面のCSS Gridでは、内容に応じた最終的な列幅に差が出る場合があります。

投稿者などの権限で保存された幅未指定の列も読み込めます。以前の版で再読み込み後に不整合と誤判定された表は、修正後のプラグインで編集画面を再読み込みすると操作できるようになります。行・列数の不一致や不正な結合幅がある表については、引き続き構造操作を拒否します。

横スクロールを有効にした表は、説明付きのフォーカス可能な領域で囲みます。狭い画面では表の構造を保ったまま左右キーでスクロールできます。スクロール設定は明示的に選択し、既定ではフォーカス用のラッパーを追加しません。有効時は広い画面で実際にはあふれていない場合もフォーカス可能です。

編集画面はdiv/CSS Grid、公開画面はPHPで `table > thead/tbody/tfoot > tr > td/th` を生成します。ブロックの入れ子構造と本文は標準のブロックコメントとして保存し、公開時にセル内の子ブロックをWordPressの描画APIで処理します。公開用JavaScriptはありません。

## 配布ZIPとライセンス

ライセンスは **GPL-2.0-or-later** です。原文は [LICENSE](LICENSE) を参照してください。

`npm run package` でルートに `modular-table-blocks.zip` を作成します。WordPressの「プラグイン → 新規プラグインを追加 → プラグインのアップロード」からインストールできます。実行用PHP・生成物・翻訳に加え、ライセンスと再ビルド用の `src/`、`package.json`、TypeScript・webpack設定を同梱します。`node_modules`、Git情報、IDE設定、wp-env設定、テストは同梱しません。ZIP内のソースを再ビルドするには `npm install`、`npm run build` を実行します。検証用ファイルと依存固定用の `package-lock.json` は開発リポジトリにあります（WordPress ScriptsのZIPにはnpmの梱包規則によりロックファイルが含まれません）。

ZIPは生成物としてGit管理から除外します。配布前には翻訳を再生成し、`npm run package` と両環境の `test:package` を実行してください。バージョンは開発中の `0.1.0` のままです。ZIP作成は公開リリースやタグ作成を意味しません。

Gitにはソース、実行に必要な `build/` と翻訳ファイル、再現可能な開発に必要な `package-lock.json`・共通設定を含めます。個人のIDE設定（`.vscode/`・`.idea/`）、ローカルの `.env`・wp-env上書き設定、依存パッケージ、キャッシュ、テスト結果、ログ、一時ファイルは `.gitignore` で除外します。環境変数の記入例 `.env.example` などは共有できます。

## スタイル設定とキーボード操作

文字色・文字サイズ・行間・水平揃えは `block.json` の標準サポートを使用します。旧 `styleTokens` の該当項目と `horizontalAlign` は、投稿の読み込み時に標準属性へ変換し、次回保存に反映します。元の値と本文を保持し、未編集の旧形式もPHPで描画できます。本文の段落・見出しなどに明示されたスタイルは優先します。標準の文字サイズ等が表示されない場合は「タイポグラフィ」のオプションから項目を表示します。可変タイポグラフィーはWordPressの標準処理に従い、同じ設定のコア段落と同じ寸法になります（編集用iframeと公開ページの表示幅が異なると、計算結果にも差が出ます）。

罫線と余白は「スタイル」タブの別パネルで設定します。罫線は標準グループと同じBorderBoxControlを使用し、色・種類・太さを1つの入力欄で設定できます。連動ボタンで一括指定と上下左右の個別指定を切り替えます。影の設定は追加していません。

セル余白は「サイズ」パネルのSpacingSizesControlを使用し、テーマのサイズプリセット・スライダー・単位付き数値入力を標準グループと同じ操作で利用できます。方向指定のUIはWordPressの版に従い、6.6では余白のオプションメニュー、新しい環境では連動ボタンから切り替えます。表示の切り替えだけでは設定値を変更しません。

辺の入力欄を空にすると、その辺の個別設定を解除して親の値を引き継ぎます。パネルのオプションから設定全体をリセットできます。罫線パネルのリセットでは余白を、サイズパネルのリセットでは罫線を維持します。単位は数値欄の中で切り替えます。背景色はColorPaletteControlでテーマの色・カスタム色を選びます。テーマの `theme.json` や従来の `editor-color-palette` で登録した色、サイト側で追加した色を取得します。ブロック別パレットと既定色・カスタム色の許可設定も反映します。RGBやCSS変数によるテーマ色も候補に表示し、選択時は色のプリセット参照を保存します。テーマCSSにだけ定義され、パレットへ登録されていない色は候補になりません。

公開表は `border-collapse: collapse` のため、共有する辺は隣接セルとの罫線競合規則に従います。一方の辺を幅0にしても、隣接セルの罫線が残る場合があります。

設定の解除は該当項目の属性とCSS変数だけを除去し、兄弟セルの設定や本文を維持します。行とセルには位置を示す補足説明を付け、Gutenbergが管理するブロック名と選択・リストビューを維持します。構造メニューはキーボードでも操作でき、確認画面はEscapeで閉じると元のボタンへフォーカスが戻ります。

アクセシビリティの自動検査は、読みやすい配色の検証用データを使い、プラグインの設定UIと公開表に限定してWCAG 2 A/AA・2.1 AAの該当ルールを検証します。利用者が指定するすべての配色や、サイト全体の適合を保証するものではありません。スクリーンリーダー実機とドラッグ操作の網羅的な確認は未実施です。

## 日本語と翻訳ファイル

日本語（WordPressのロケール `ja`）を同梱しています。WordPressの「設定 → 一般 → サイトの言語」、またはユーザーのプロフィールの言語を「日本語」にすると、ブロック名・説明・設定項目・案内・エラー表示が日本語になります。それ以外の言語で翻訳がなければ英語を表示します。

- `languages/modular-table-blocks.pot`：他の言語にも使える翻訳テンプレート。
- `languages/modular-table-blocks-ja.po`：日本語訳の編集元（85件）。Poeditなどで編集できます。
- `languages/modular-table-blocks-ja.mo`：PHP・ブロックメタデータ用の翻訳。
- `languages/modular-table-blocks-ja-*.json`：編集画面のJavaScript用翻訳。
- `languages/map.json`：ブロックメタデータの翻訳を共有スクリプトへまとめる対応表。

POを変更した後は、専用のwp-envを起動して再生成します。

```sh
npm run env:start
npm run i18n:build
```

UIの英語文言を変更した場合は、先に `npm run build` と `npm run i18n:pot` を実行し、POをPOTに同期して翻訳を追加してから `npm run i18n:build` を実行してください。POTは実際の配布用JS・メタデータから抽出し、JSON生成では `--no-purge` によりPO内のJavaScript翻訳を保持します。MO・JSONは生成物なので直接編集しません。

JavaScript翻訳JSONのファイル名末尾は `build/index.js` の相対パスのハッシュです。入口の出力パスを変更した場合は、翻訳JSONも再生成してください。

## CSSカスタムプロパティ

既定値は `var()` のフォールバックです。ブロックに既定トークンを宣言せず、未設定なら上位スコープから継承します。編集・公開で同じSass mixinを使用します。

| トークン | フォールバック | 参照する要素 |
| --- | --- | --- |
| `--mtb-text-color` | `inherit` | テーブル・行・セル |
| `--mtb-background-color` | `transparent` | テーブル |
| `--mtb-cell-background-color` | `transparent` | セル |
| `--mtb-border-color` | `currentColor` | セル |
| `--mtb-border-width` | `1px` | セル |
| `--mtb-border-style` | `solid` | セル |
| `--mtb-cell-padding-block` | `0.75em` | セルの上下余白 |
| `--mtb-cell-padding-inline` | `1em` | セルの左右余白 |
| `--mtb-cell-padding-top/right/bottom/left` | 上記の軸別値 | セルの四辺の余白（各方向を個別指定） |
| `--mtb-border-top/right/bottom/left-color/width/style` | 対応する一括罫線値 | セルの四辺の罫線（方向・項目ごとに個別指定） |
| `--mtb-font-size` | `inherit` | テーブル・行・セル |
| `--mtb-line-height` | `inherit` | テーブル・行・セル |
| `--mtb-table-width` | `100%` | テーブル |
| `--mtb-column-width` | `auto` | 各 `col`（列幅設定から出力） |
| `--mtb-scroll-min-width` | `40rem` | 横スクロール有効時のテーブル（テーマCSSで変更） |

優先順位の意図は「フォールバック → サイト → テーブル → 行 → セル」です。通常のCSSカスケードが適用されます。同じ要素への詳細度や宣言順なども影響します。標準の文字サイズは指定したブロックで計算し、未設定の子は計算済みのサイズを継承します。旧形式で `em` / `%` が各階層で再適用されていた表示は改善されます。文字サイズ・文字色・行間の標準設定が明示されたスコープでは、対応する旧トークンを `initial` にして、祖先の旧トークンの再適用を遮断します。標準設定がないスコープの旧トークンは引き続き使用できます。

公開側の `table` 本体は既定で `border: none` とし、テーマの外枠とセルの罫線が重ならないようにします。罫線設定の `--mtb-border-*` は引き続きセルへ適用します。テーブル本体の外枠を追加したい場合は、`:root table.wp-block-modular-table-blocks-table.my-table { border: 2px solid #333; }` のように個別クラス付きのCSSで指定できます。

公開側のセルには、表・行・セルのプラグイン固有クラスを組み合わせてスタイルを適用します。テーマの一般的な `td` / `th` 指定よりプラグインの罫線・色・余白などを優先し、水平揃えの未設定時は上位から継承、文字分割は `word-break: normal` / `overflow-wrap: anywhere` とします。テーマの `padding: … !important` に対応するため、公開セルの余白宣言だけに `!important` を使用します。値は引き続き `--mtb-*` から取得するので、以下のトークン指定には `!important` は不要です。ブロック属性の一括・軸別指定は、そのスコープの四辺の変数にも展開するため、親の辺指定より子の一括指定を優先できます。CSSで辺指定も併用する場合は、必要な辺の変数も対象スコープで上書きしてください。

この調整はプラグインのセルに限定され、通常のテーブルやセル内のコアブロックを一括リセットしません。テーマがさらに強いセレクターや他のプロパティの `!important` を使用する場合は、競合するテーマCSSの調整が必要になることがあります。カスタマイズには、実プロパティの詳細度を競わせるより `--mtb-*` を使用してください。

テーマから設定する例：

```css
:root {
  --mtb-text-color: var(--wp--preset--color--contrast, #222);
  --mtb-border-color: #d4d4d4;
  --mtb-cell-padding-inline: 1.25rem;
}

/* テーブルの「追加CSSクラス」に my-table を設定 */
.my-table {
  --mtb-border-color: #2563eb;
  --mtb-cell-padding-inline: 2rem;
}

.my-table > tbody > tr:first-child {
  --mtb-cell-background-color: #eef2ff;
}

.my-table > tbody > tr:first-child > :first-child {
  --mtb-text-color: #1e3a8a;
}
```

サイト共通CSSを編集キャンバスにも反映する場合は、テーマ側で同じCSSをエディターへ読み込んでください。公開ページの `:root` とエディターiframeの `:root` は別の文書です。`theme.json` やコア段落の個別スタイルは通常どおり適用されるため、本文ブロックの明示設定がセルからの継承に優先する場合があります。

文字色・文字サイズ・行間・水平揃えは、標準の `textColor`・`fontSize`・`style` 属性に保存されます。罫線・余白・背景色・表幅は `styleTokens` 属性に保存されます。有効かつ明示された値だけをテーブルの `table`、行の `tr`、セルの `td/th` の `style` に出力します。

| 設定値 | 許可範囲 |
| --- | --- |
| 色 | 3/4/6/8桁の16進色、`transparent`、`currentColor`、`inherit` |
| 罫線幅 | `0`、0〜20px、0〜1rem/em |
| 罫線種類 | `none`、`solid`、`dashed`、`dotted`、`double` |
| セル余白 | `0`、0〜200px、0〜10rem/em |
| 文字サイズ（旧トークン） | 8〜160px、0.5〜10rem/em、50〜500% |
| 行間（旧トークン） | `normal`、0.5〜4の単位なし数値 |
| テーブル幅 | 0より大きい100%以下、4000px以下、250rem/em以下 |

標準タイポグラフィーの入力範囲と候補はWordPressとテーマの設定に従います。上記の文字サイズ・行間の数値範囲は旧トークンの検証用です。

色は `var(--wp--preset--color--contrast)`、文字サイズは `var(--wp--preset--font-size--large)`、セル余白は `var(--wp--preset--spacing--40)` の形式も使用できます。プリセット名は英小文字・数字・単語間ハイフンのみです。任意の `var()`、`calc()`、URLや複数宣言の入力は受け付けません。テーマCSSでは通常のCSS値を使用できます。

## 開発コマンド

```sh
npm run start          # 監視ビルド
npm run build          # JS / CSS / block.json / index.asset.php を生成
npm run check-types    # TypeScript
npm run lint           # WordPress推奨ESLint + Sass対応Stylelint
npm run test:unit      # グリッドとスタイル値の検証
npm run test:php       # WP 6.6で登録・描画・保存ツリー・値検証
npm run test:e2e       # WP 6.6でChromium全E2E
npm run test:e2e:latest # WP 7.1.3でChromium全E2E
npm run test:e2e:compat # 両WPでFirefox・WebKitの結合とM3検証
npm run package        # ビルドして配布ZIPを作成
npm run test:package   # WP 6.6でZIP展開物の登録・描画を検証
npm run test:package:latest # WP 7.1.3でZIP展開物を検証
npm run env:stop       # WP 6.6環境を停止
npx wp-env stop --config=.wp-env.latest.json
```

`build/index.asset.php` の依存とバージョンで共通ハンドル `mtb-editor` を登録し、3つの `block.json` から参照します。WordPress提供パッケージはバンドルせず、公開CSSと編集UI用CSSは別に読み込みます。

## 対応範囲と残る制約

- セル内の許可ブロックは段落・リスト・見出し・画像・ボタンです。入れ子テーブルは対象外です。
- 行・セル単位の自由な挿入・削除・並べ替えは構造を壊すためロックし、専用操作からテーブル全体を更新します。結合範囲は左上セルから指定し、Excel型のドラッグ範囲選択はありません。
- 行の `section` を個別に指定したデータは、先頭の連続した見出し行と末尾の連続したフッター行を `thead` / `tfoot` へ、それ以外を `tbody` へ正規化して順序を保ちます。その表の構造操作は拒否します。通常はテーブルの見出し行設定を使用します。
- 縦結合に影響する行の移動・複製や、見出し境界をまたぐ結合は拒否します。先頭行をまたぐ結合がある場合は、分割してから見出し行を有効にしてください。
- 縦結合の編集レイアウトはCSS Gridのsubgridを使用します。WordPress 6.6と7.1.3でPlaywright Chromium・Firefox・WebKitによる検証を行います。subgrid非対応ブラウザーの編集レイアウトには対応していません。
- 編集用CSS Gridと公開テーブルはレイアウトアルゴリズムが異なり、列幅や罫線の重なりは完全一致しません。テーブルのARIAロールは編集画面に重複付与していません。
- WordPress 7.1.3とFirefoxでは、リストビューから戻って段落をクリックした際に、親セルが先に選択される場合があります。セル枠をクリックして編集キャンバスへフォーカスを戻した後、本文をクリックして入力する操作を検証しています。
- E2Eは結合・分割、構造操作・Undo/Redo・削除確認・確認中の変更拒否、リストビューの行選択、クリップボード貼り付け、管理者・投稿者によるリッチコンテンツの保存復元、表示設定・キーボード横スクロールを検証します。ドラッグ操作や支援技術による網羅的検証は後続課題です。
- 継承スタイル設定はWordPress 6.6で公開されているColorPalette・RangeControl・SelectControl・Buttonなどを使用します。寸法の単位変更は数値を新しい単位で解釈し、許可範囲へ収めます。変更前の単位からの物理的な換算は行いません。
- WordPress 6.6の `SCRIPT_DEBUG` 有効時、コアの `createRoot` 読み込みに関するReact警告が発生します。E2Eはこの完全一致の警告を注記し、それ以外のコンソールエラーとブロック検証エラーを検出します。
- インストール時に開発依存のengine・audit警告が出る場合があります。今回の検証環境はNode.js 24.14.1／npm 11.12.1です。Playgroundランタイムは未使用で、wp-envはDocker方式を使用します。

設計判断と実行した検証は `docs/decisions/` に記録します。
