# M2：結合・分割と構造操作

## 変換と内容の保持

保存データは従来どおり行・セルのブロックツリーと列設定とし、結合はセルの `colSpan`・`rowSpan` に保存する。`layout.ts` で占有グリッドから起点・列位置・結合範囲を求め、`operations.ts` が純粋な変換計画を返す。計算した配置やclientIdを属性へ保存しない。

結合範囲は、選択した左上セルから行数・列数で指定する。既存の結合セルを部分的に含む範囲と、見出し境界をまたぐ範囲は拒否する。内容は元セルの起点の読み順で左上セルへ移し、すべての入れ子ブロックを保持する。左上セルの種類・scope・スタイルを採用し、他のセルの設定は引き継がない。この規則は結合確認画面にも表示する。

分割では内容を左上セルに残し、同じセル設定を持つ空セルを作る。以前の配置や個別設定を復元する二重データは保存しない。元の状態へ戻す操作はUndoとする。結合・分割もテーブル全体の1回の `replaceBlocks` で適用し、既存の本文ブロックの識別子を保つ。

## 行・列の操作

- 結合範囲の内側への挿入では結合数を広げ、外側では元の結合を保って位置を移す。新しい行・列の未占有位置だけに空セルを作る。
- 削除が結合に重なる場合は結合数を減らす。元の行が削除されても縦結合が残れば、内容を持つ起点セルを次の行へ移す。
- 最後の占有行・列が消えるセルだけを削除し、そのセルに内容があれば確認する。縮小して保持する結合セルの内容は削除しない。
- 縦結合に影響する行の移動・複製は曖昧なため拒否する。横結合だけの行や、縦結合に触れない行の移動・複製は許可する。
- 変換後もグリッドと見出し境界を検証する。先頭行をまたぐ縦結合がある場合は、見出し行設定の有効化を拒否する。行の個別section指定がある表は引き続き構造操作を拒否する。

## 編集DOMと操作UI

操作はブロックツールバーに集約し、設定サイドバーは拒否理由とエラーの通知だけに使用する。結合範囲の指定にはGutenbergのModalとSelectControlを使用する。適用前に確認開始時のテーブルと最新のテーブルが同じか調べ、古い範囲による変更を拒否する。

行ごとに独立したGridでは縦結合を表現できないため、テーブルの行リストを共有Gridにし、行ラッパーの列・行をsubgridで共有する。セルは論理列と結合幅へ配置する。行ラッパーは必要な行数を覆うが、ポインターを受けるのはセルとし、下側の行ラッパーが縦結合の入力を遮らないようにする。行ラッパー自体は残し、リストビュー選択とキーボードフォーカスを維持する。

行・セルの外枠には `align-self: stretch` と自動の高さを明示し、テーマが指定する上揃え・`height: fit-content`・ブロック余白による縮小を防ぐ。セル内部の垂直揃えは従来の `align-content` で制御する。隣のセルを高くした横結合・縦結合・長方形結合で、結合範囲の上端・右端・下端を実DOMから測定する。通常のテーマ設定に加え、前述の高さ・余白指定を注入した条件でも、入力と垂直揃え変更後まで検証する。

配置はReact Contextから子ブロックへ渡し、直接DOMを書き換えない。未選択のブロックでは構造操作の計画を生成しない。公開側は従来のPHPレンダラーで意味的なtable/tr/td/thと結合属性を出力し、公開用JavaScriptは追加しない。

## 検証範囲と残る制約

単体テストは3×3の各長方形と全挿入・削除境界を検証し、重複・欠落・内容の消失・元データの変更を検出する。E2Eは実際の結合セルの寸法、下側へのクリック、結合・分割、Undo/Redo、保存復元、リッチコンテンツ、投稿者権限、変更中の確認拒否を扱う。PHPでは結合した内容が1回だけ描画され、完全に覆われた行も残ることを確認する。

ブラウザー検証はWordPress 6.6と7.1.3上のPlaywright Chromiumで行う。subgridを含む他ブラウザー、支援技術、自由なドラッグ操作の網羅的確認はM3に残す。継承スタイルのUI改善はM3の範囲を維持する。
