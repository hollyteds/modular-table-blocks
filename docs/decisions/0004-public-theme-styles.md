# 公開セルとテーマのスタイルの優先関係

## 問題と変更

従来の公開CSSは `:where()` で詳細度をゼロにしていたため、テーマの一般的な `td` / `th` 指定にも負けていた。属性や `--mtb-*` に設定値が残っていても、セルで参照する実プロパティが上書きされ、罫線・余白などに反映されなかった。特に `padding: … !important` は通常宣言の詳細度を上げるだけでは上書きできない。

公開側では表・行・セルのプラグイン固有クラスを組み合わせ、実プロパティの適用先と優先度を確保する。セクションの `:where(thead, tbody, tfoot)` は維持する。余白の論理プロパティ2つに限って `!important` を使用し、値は共通mixinから従来と同じトークンとフォールバックで取得する。編集側のmixin呼び出しでは重要指定を付けない。

水平揃えは上位からの継承を既定とし、個別セルのインライン指定を維持する。テーマの `word-break: break-all` は `normal` に戻し、長い文字列は `overflow-wrap: anywhere` で折り返す。特定テーマの変数名や読み込み順には依存しない。保存形式、PHP描画、公開JavaScriptは変更しない。

## 継承と適用範囲

`--mtb-*` の既定値を各セルに宣言しないため、サイト→表→行→セルの継承と個別設定を維持する。重要指定は実際の余白宣言に付くが、トークンには付かない。テーマや利用者は通常のトークン指定でカスタマイズできる。

`all: unset` / `all: initial` による一括リセットや、全プロパティへの重要指定は採用しない。通常のテーブルとセル内のコンテンツはセレクターの対象に含めない。CSSカスケード自体を隔離する方式ではないため、さらに強いセレクターや、余白以外へのテーマの重要指定は個別の調整が必要になる場合がある。

## 検証

`theme-styles.spec.ts` は公開ページへプラグインより後から2種類のCSSを読み込み、一般的なタグ指定と、詳細度を上げた指定で競合を検証する。修正前は個別余白17pxがテーマの41pxになり、両方のテストが失敗することを確認した。

修正後は見出しセル・通常セルの四辺の罫線と余白、余白0・罫線なし、水平・垂直揃え、背景色・文字色、文字分割、複数テーブル、サイト・表・行・セルの継承、トークンの変更、375px幅での意味的な表示を検証する。別のコアテーブルではテーマの余白・文字色が残ることを確認する。検証にはPlaywright Chromiumを使用する。

## テーブル本体の罫線

公開 `table` 本体の罫線は既定で非表示にする。`:root table.wp-block-modular-table-blocks-table` に `border: none` を指定し、テーマの一般的な `table` / `:root table` の外枠がセルの罫線へ重ならないようにする。`--mtb-border-*` の値は消さず、従来どおりセルで参照する。`!important` は使わず、個別クラスを併用した明示的な外枠のCSSは適用できる。

回帰テストでは、プラグインCSSより後にテーマの17pxの罫線を適用し、表本体の四辺が非表示、`td` / `th` の罫線が設定どおりであることを確認する。セル罫線なし、複数テーブル、通常のコアテーブル、375px幅、明示的な外枠の上書きも対象とする。

追加修正後の検証では、ビルド・型検査・lint・単体118件が成功。WordPress 6.6と7.1.3で `theme-styles.spec.ts` 各4件が成功し、375px幅の公開表示も確認した。配布ZIPは生成していない。
