# M1：構造操作と公開表示

## 構造の変換

`src/grid/operations.ts` は現在のブロックツリーから変更計画（`changes`・`warnings`・`errors`）を返す純粋関数とする。列設定と行・セルのツリーが保存データの正本であり、別のグリッド配列を永続化しない。

M1では結合のない整合したグリッドだけを操作する。行の追加・削除・複製・上下移動、列の追加・削除を扱う。最後の行・列の削除、上限超過、結合セルを含む構造操作、不整合な入力、行の個別セクション指定がある場合は拒否する。結合を考慮した変換はM2に残す。

行・セルの標準追加・削除・移動はInnerBlocksのテンプレートロックで制限し、専用操作からテーブル全体を更新する。適用直前に最新の状態を読み直し、画面で計画した状態や削除確認の開始時点と異なれば拒否する。内容のある行・列を削除するときはモーダルで確認し、キャンセル時には変更しない。

行・列の挿入・複製・移動・削除は、テーブル・行・セルを選択したときのブロックツールバーに集約する。設定サイドバーに構造操作のボタンは置かず、拒否理由やエラーがある場合のみ通知を表示する。

ツールバーへの集約後、テーブル・行・セルそれぞれのメニュー項目、サイドバーに操作ボタンがないこと、Escapeでのメニュー閉鎖を実ブラウザーで検証した。構造操作・削除確認・Undo/Redo・内容保持の既存E2Eもツールバー経由へ変更し、WordPress 6.6・7.1.3で各13件が成功した。ビルド・型検査・lint・単体テスト72件も成功した。

テーブル属性と子ツリーを別々に更新する方式は列数と内容のUndoが分かれる可能性があるため採用しない。公開APIの `replaceBlocks` 1回で所有テーブルを置き換え、選択中の行・セルが残っていれば再選択する。既存の無関係な行・セル・本文ブロックは識別子と属性を保持し、新しい編集用clientIdは新規ブロックと複製だけに割り当てる。テーブルルートのclientIdは置き換え時に変わるが永続化しない。

既存のリッチテキスト属性はWordPressの内部表現でオブジェクトになる場合がある。複製で新規作成APIの属性正規化にかけると内容を失うため、既存ブロックの複製には公開APIの `cloneBlock` を使用する。新しい空セル等は `createBlock` で作成する。テストで属性をブラウザー外へ転送すると内部表現が変わるため、本文比較はブラウザー内で文字列化して行う。

## 見出し・列幅・揃え

見出し行のUIは `headerRows` を0または1にする。見出しは位置に基づき、元のセルの `tag`・`scope` を書き換えず、公開描画時に `th scope="col"` を適用する。設定を解除すれば元のセル属性で描画する。編集側でも先頭行と個別の見出しセルを強調する。

手入力等で存在する行の `section` は、先頭の連続した見出しと末尾の連続したフッターだけをそれぞれ `thead`・`tfoot` として扱い、中央は `tbody` とする。内容の順序は変えない。rowSpanの描画はセクション内の残り行数までに制限する。

列幅はテーブルの `columns` に保持する。TypeScriptとPHPで幅の型・単位・範囲を検証し、公開側では `colgroup > col` の `--mtb-column-width`、編集側ではCSS Gridの列定義へ反映する。編集画面では各列に8remの最小幅を確保し、幅が足りなければテーブル内を横スクロールできるようにする。これにより、40%・60%の列の間へ追加した空列も入力可能な幅を保つ。公開側のテーブルレイアウトと編集画面のGridは別の計算方式であるため、内容に応じた最終幅の差は残る。

水平・垂直揃えはセル属性に保存し、許可値のみを編集・公開へ適用する。既存の継承スタイル設定は変更しない。スタイルUIのGutenbergコンポーネント化はM3の対象である。

## 横スクロールとコンテンツ

横スクロールは明示的に有効にした場合にだけ `overflow-x: auto` のラッパーを追加する。領域には説明と `tabindex="0"` を付け、キーボードで横スクロールできるようにする。公開用JavaScriptは追加しない。

実際のオーバーフローをPHPだけで判定することはできないため、横スクロール有効時は広い画面であふれていない場合もフォーカス可能になる。この制約をREADMEに記載する。既定のモードではラッパーやフォーカス順序を追加しない。狭い画面でも `tr`・`td/th` の表構造を維持する。

セル内は段落・リスト・見出し・画像・ボタンを許可する。本文はWordPressの描画APIで処理し、行・セル間にエディターのラッパーを混入させない。入れ子テーブルや任意の追加ブロックの許可は対象外とする。

### 入力時の幅縮小の修正

テーマの `.editor-styles-wrapper .wp-block` に左右の `margin: auto` が指定されると、Gridのセルが内容幅で中央に配置される。ブラウザーでこのCSSを適用すると、空の段落に1文字入力した時点でセルの幅が約231pxから45pxへ縮むことを再現した。

編集用セルに `width: 100%`・`box-sizing: border-box`・`max-width: none` を指定して列幅を満たすようにし、内部のGrid列も `minmax(0, 1fr)` とした。直下の段落・見出し・リストも内容領域の幅を満たすようにする。画像・ボタンの個別幅や配置、公開CSS、保存属性は変更しない。

回帰テストでは自動幅・割合幅・固定幅の各ケースでテーマの中央配置CSSを適用し、空欄・1文字・長文・文字削除後のセル幅と段落幅を実DOMで測定する。

修正後はWordPress 6.6・7.1.3の両方で追加3件を含むE2E全12件が成功した。ビルド・型検査・lint・単体テスト72件・両環境のPHP描画テストも成功した。

### 保存・再読み込み後の不整合判定

投稿者など `unfiltered_html` を持たないユーザーでは、WordPressのKSES処理が保存本文のブロック属性をPHPでパース・再シリアライズする。幅未指定の列の `{}` はこの処理で `[]` になる。構造操作の検証が配列をすべて拒否していたため、内容と行列数が保たれていても、再読み込み後に不整合と判定していた。管理者での従来の保存テストでは検出できなかった。

列設定の読み込みで、空配列のみを幅未指定の空オブジェクトと同等に扱う。変換計画では空オブジェクトへ正規化するが、元データは変更しない。幅指定のある列設定とセル内の内容を保持し、非空配列・null・文字列などの不正な列設定は引き続き拒否する。保存本文の書き換えや、行列の自動修復は行わない。

管理者・投稿者の両方で、保存・再読み込み・列挿入・再保存・再読み込みを検証するE2Eを追加した。テスト用投稿者は専用のwp-env内で作成し、ログインにはPlaywrightのHTTPリクエストを使用する。ログイン画面のフォーカスが自動で移ることによるテストの失敗も避ける。

修正後はWordPress 6.6・7.1.3で各15件のE2Eが成功した。空配列の互換読み込みと不正な列設定の拒否を含む単体テスト79件、ビルド・型検査・lint・両環境のPHP描画テストも成功した。
