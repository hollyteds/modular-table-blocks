# 開発資料の入口

このディレクトリには、現行の機能を実装・修正するための資料を置く。過去の変更順をたどらず、以下の現行文書と該当するコード・テストで作業を進める。

## 読む順序と正本

1. [AGENTS.md](../AGENTS.md)：作業規約・変更と検証の進め方。
2. [ARCHITECTURE.md](ARCHITECTURE.md)：現行の機能・保存・描画・操作の契約。実装を変更する際は該当節を読む。
3. [DEVELOPMENT.md](DEVELOPMENT.md)：環境構築、コマンド、翻訳、配布とリリースの手順。
4. [STYLING.md](STYLING.md)：CSSを変更する場合の公開カスタムプロパティ・適用先・テーマ連携。

導入ユーザーの説明は[ルートのREADME](../README.md)、利用者に影響する変更の要約は[CHANGELOG.md](../CHANGELOG.md)、ライセンスは[LICENSE](../LICENSE)と[THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)を参照する。

## 情報を記載する場所

| 情報 | 正本 | 更新方法 |
| --- | --- | --- |
| 機能・保存属性の意味・編集と公開の動作・継承・安全な変更の条件 | ARCHITECTURE.md | 機能別の既存節を更新する |
| ブロック属性の登録と既定値 | 各ブロックのblock.json | 設計と一致することをコード・テストで確認する |
| 表の寸法・初期作成の上限 | includes/table-limits.json | TypeScriptとPHPで共有する検証値を更新する |
| CSS名と保存値の展開先 | includes/style-tokens.json | CSS公開仕様と実装を同時に照合する |
| 環境構築・検証・翻訳・配布の操作 | DEVELOPMENT.md | 手順と既存スクリプトを一致させる |
| 公開CSS名・既定値・テーマ向けの使い方 | STYLING.md | 一覧と例を更新する |
| エージェントの作業規約 | AGENTS.md | 製品仕様を複写せず現行文書を参照する |
| 操作説明 | ルートのREADME.md | 導入ユーザーの言葉で更新する |
| 変更の結果・利用者への影響 | CHANGELOG.md | Unreleasedへ追記する |

日付順の追補や、同じ仕様の別文書への再記載で現行仕様を増やさない。実装と文書に差異があればコード・実DOM・テストで確認し、差異を報告して、対象範囲の実装と正本を揃える。未実装の機能や未実行の検証を完了として記載しない。

## 暫定的な履歴資料

`docs/decisions/`は開発途中の経緯・採用しなかった案・その時点の検証結果を残す暫定資料。古い仕様、後から置き換えたUI、当時のテスト件数を含むため、現行仕様の根拠として優先しない。通常の実装で全件を読む必要はない。

この履歴資料はGit管理対象外のローカル資料であり、新規チェックアウトには含まれない。恒久的な仕様書や配布必須物にせず、履歴がなくても実装・検証・リリースできることを維持する。現行文書・コード・テストから履歴資料への必須リンクを追加しない。ローカルで履歴を追加する場合も、現在必要な仕様と制約は先に正本へ反映する。

除外方針と追跡解除時の確認事項は[開発手順](DEVELOPMENT.md#暫定履歴資料のgit管理からの除外)に記載する。
