# Modular Table Blocks — 現行仕様

2026-10-29時点の機能・保存・描画・操作の契約を、機能別にまとめた正本。仕様変更では該当節を更新する。過去の判断記録を読まなくても実装を進められる内容を維持する。作業規約は[AGENTS.md](../AGENTS.md)、手順は[DEVELOPMENT.md](DEVELOPMENT.md)、公開CSSの一覧・既定値・使用例は[STYLING.md](STYLING.md)を参照する。

## 1. 対象と境界

- WordPress 6.6以上、PHP 7.4以上。Block API v3を使用する。
- テーブル直下へセルブロックを配置する。行ブロック・行別スタイル・列ブロックは持たない。
- 編集画面はdivと単一のCSS Grid、公開側はPHPが描画する意味的tableとする。公開用JavaScriptは追加していない。
- 表計算・並べ替え・絞り込み・Excel型のドラッグ範囲選択・入れ子テーブル・コアテーブルのあらゆる形式からの自動移行・カード表示への自動変換は対象外。
- 未リリースの旧table→row→cell形式の互換描画・自動移行は提供しない。現在のスタイル属性を読む際の標準属性への正規化は、行ブロック形式の移行とは区別する。

## 3. ブロックと保存データ

```text
modular-table-blocks/table
└── modular-table-blocks/cell
    └── modular-table-blocks/cell-text または許可された通常ブロック
```

| 管理主体 | 保存する値 | 制約・既定 |
| --- | --- | --- |
| テーブル | rowCount、columns、columnWidthMode、headerRows | rowCount=0は未作成。作成時は1〜20行・列、通常の操作と取り込みは最大100行・50列。初期作成UIは3×3 |
| テーブル | caption、captionEnabled、captionSide、captionAlign、responsiveMode、borderCollapse、stripeMode | キャプション・スクロール・罫線の共有／分離・背景ルール |
| テーブルとセル | 標準の色・タイポグラフィー属性、styleTokens、verticalAlign | スタイルの二階層。行別の保存先を追加しない |
| セル | row、column、rowSpan、colSpan、tag、scope | 座標は0始まり。spanは正整数で未指定は1。tagの既定はtd |
| セルテキスト | content | source:htmlの文字列、既定は空文字。文字・改行・標準インライン書式 |
| その他の子ブロック | 本文・画像など | Gutenberg標準のブロックツリーとシリアライズ |

各[block.json](../src/blocks/)を登録情報の正本とする。行列・初期作成の上限は`includes/table-limits.json`をTypeScriptとPHPで共有し、取り込み文字数の上限は取り込み側で管理する。columnsは列の幅などのメタデータを保持する。計算用の二次元占有配列・計算された列幅・編集状態・clientIdを永続化しない。セルのブロックツリーと明示座標が正本で、保存順から座標を推測しない。rowCountにより開始セルのない、縦結合に覆われた行も保持する。

tableのallowedBlocksはcellのみ、cellのparentはtable、cell-textのparentはcellのみとする。tableとcellはそれぞれInnerBlocks領域を1つ持つ。table自身のtemplateLock="all"はセル構造を保護するためのもの。ユーザーが付けたロック・祖先のテンプレート制約とは区別して専用操作を設計する。

### セル内容

- セル直下は「セルテキスト1つ」または「通常ブロック複数」の排他構成。通常ブロックは段落・リスト・見出し・画像・ボタンを許可し、グループ（core/group）は許可しない。登録情報と編集用許可リストを揃え、既存データのグループは読み込み時に自動削除しない。
- 新規作成・行列挿入・結合解除で増えたセルにはemptyCellを使い、空のセルテキストを1つ置く。既存セルや削除後のセルへの自動挿入は行わない。
- 空セルは両構成を選べる。候補の先頭はセルテキスト。空セルのdefaultBlockはセルテキスト、既存内容のあるセルは段落。directInsertはfalseとする。
- 空セルと通常ブロックのセルではrenderAppenderを指定せず標準の追加ボタンを使う。セルテキスト配置済み・混在セルは追加ボタンを非表示にする。通常ブロックがあるセルではセルテキストを候補から外す。
- 複製・挿入・ブロック貼り付け・移動・置換は操作全体の更新前に検証し、混在する変更を拒否する。読み込み・Undo/Redoでは既存内容を自動削除せず、混在警告と段落変換・削除による整理を許可する。外部API向けのサーバー側強制削除は行わない。
- セルテキストはRichText標準の太字・斜体・リンクなどのインライン書式を許可する。ブロック全体の色・位置・HTML編集・クラス・アンカー・改名・ロック・再利用等の設定は追加しない。
- セルテキストから段落への標準変換で文字・改行・インライン書式を保持する。文字として入力したHTMLをタグへ復号しない。通常の本文内ペーストはRichText標準の処理を維持する。
- 公開時はp/div等のラッパーを付けず、許可されたインラインHTMLを検証して出力する。境界の空白・文字としての数値文字参照を保存復元で保護する。複数ブロック間の区切りを勝手に追加しない。

## 4. グリッド・構造操作

buildGridで寸法・明示座標・正のspan・範囲・重複を検証し、validateGridで欠損も検出する。CellRefのcellIndexはテーブル直下のセル配列の添字で、行内の添字ではない。構造が不正なら本文を保持して操作を拒否し、黙った補修や切り捨てを行わない。

planOperation等の純粋関数で変更・警告・エラーを計画し、最新の表で再検証してから編集ストアへ一貫して反映する。元データ・無関係な子ブロックを破壊せず、構造変更を1回のUndo/Redoへまとめる。構造操作の表示と確認状態は`components/structure/use-structure-editor.ts`、確定時の検証・更新は`editor/structure.ts`が担当する。`editor/materialize.ts`で既存IDとRichText属性を保持し、複製ではIDだけを再生成、新規ノードだけを登録スキーマから生成する。内容やロックを削除する確認では、確認時のスナップショットも再検証する。

### 行・列

- 行・列の追加・削除・複製・移動はツールバーのみ。table選択時は末尾追加、cell選択時はその位置の前後挿入・複製・削除を表示する。
- 移動は独立した「行・列の移動」メニューで、行を上下・列を左右へ1つずつ移動する。既存セルのID・選択を保つ。列の複製は右隣に追加する。
- 対象外の内容、セル設定、列幅・列メタデータを保持する。複製では子ブロックも複製し、編集用IDを新しくする。
- 結合内への挿入はspanを広げ、重なる行列の削除はspanを縮める。開始行を削除しても結合が残る場合は内容を移して保持する。セルが占有する最後の行・列の削除では内容削除の確認を行う。
- 縦結合を横断する行の移動・複製、横結合を横断する列の移動・複製は拒否する。列の操作では縦結合を保持し、範囲外の横結合を変更しない。最後の行・列は削除できない。

### 結合・分割

- 「セルの結合・分割」はサブメニューを持たない単一のToolbarButtonとする。選択セルのrowSpan／colSpanから結合状態を導き、標準のisPressedで反転表示とaria-pressedを連動させる。未結合セルではクリックで結合Modalを開き、結合セルでは再クリックで直ちに分割して反転を解除する。
- 未結合セルで結合可能な終点がない場合と不正グリッドではボタンを無効にする。結合セルは追加結合の終点がなくても分割できる。選択切り替え・Undo/Redo・再読み込みで実際の結合状態へ追従し、押下状態を別属性として保存しない。
- 結合は現在セルの左上を起点にModalを開き、結合可能な最大の擬似グリッドで終点を選ぶ。「セルを結合」で確定する。Tab・矢印キー・Enter／Spaceに対応する。
- 範囲は連続した長方形で、既存の結合セルを途中で切らず、見出し行と本文の境界をまたがない。
- 起点の全子ブロック、種類・scope・スタイルを保持する。起点以外に子ブロックがあれば、空のブロックも削除確認の対象とし、位置と件数を示して明示承認を得る。
- **承認済みの結合でだけ、起点以外の対象セル・子ブロックのロックに関わらず内容を削除する。** 起点・範囲外・テーブルの内容とロックは維持する。この例外を取り込みや一般の削除へ広げない。
- 確認中に内容・構造・ロックが変わった場合は承認を無効にする。キャンセル・Escapeで変更せず、起動ボタンへ戻る。
- 分割後は起点に内容を残し、他の位置へ空のセルテキストを持つセルを生成する。削除済み内容の復元はUndoで行う。

## 5. 編集画面と公開HTML

### 編集画面

単一のCSS Gridへセルをrow/column/spanで配置し、行ラッパー・subgridは作らない。Gutenbergのラッパーをtable関連要素の間へ挿入しない。標準のブロック名・選択・リストビューを維持し、位置はaria-describedbyで補足する。編集用のtableロールを重複付与しない。

均等幅・自動幅・指定幅を論理列に適用する。自動列は全行・結合セルの内容を参照し、計算した列幅は保存しない。ラッパーはborder-boxで編集キャンバス内に収め、明示幅が大きい場合も内側のスクロールで内容を操作できるようにする。横スクロール無効時の自動列の最小幅は8remと利用可能幅÷列数の小さい方、有効時は8rem。指定列幅より大きい最小幅を強制しない。最小高さが指定された表は行を伸ばす。

### 公開側

table/cellのsaveはInnerBlocks.Contentで子ブロックコメントを保持する。PHPのルートレンダラーが寸法・配置・占有状態を検証し、各論理行のtrと各開始セルのth/tdを1回ずつ出力する。子コンテンツはWordPressのブロック描画APIを使う。不正な配置・旧行ブロック形式は表として描画しない。

```text
figure.modular-table-blocks-figure
└── table.wp-block-modular-table-blocks-table
    ├── caption（表示時だけ、tableの最初の子）
    ├── colgroup（列の設定に応じて）
    ├── thead / tbody
    │   └── tr
    │       └── th / td → 子コンテンツ
```

横スクロールが有効な場合だけ、figureとtableの間へフォーカス可能な`div.modular-table-blocks-scroll`を追加する。領域名は表示中のcaptionをプレーンテキスト化した名前等とする。非表示のcaptionを読み上げ名へ含めない。有効時は広い画面でもフォーカス可能である。tr/tdをdisplay:blockへ変えてモバイル表示を作らない。

公開側の幅・外側余白・幅広／全幅はfigure、背景・文字・最小高さ・セル共通値はtableへ1回だけ適用する。標準クラス・追加クラスはtableに維持し、selectors.spacingでテーマの余白をfigureと編集ラッパーへ振り分ける。標準属性はHTML Tag Processorで安全に振り分け、引用符・関数内の区切り・エスケープを保つ。figureの既定幅はautoとし、外側余白を差し引く独自計算や100%固定は行わない。

公開HTMLに行ブロック・編集専用のラッパーや状態を保存しない。headerRowsとセルのtag/scopeで見出しを決め、先頭列を自動的にTHへ変更しない。行のsection属性・tfoot設定は持たない。

## 6. 設定UI

### テーブル

「設定」タブの「テーブル設定」は、先頭行を見出しにする（TH）・横スクロールのトグル、全幅の「セルの一括設定」、列幅、セル間隔、テーブルの幅、キャプションの順。列幅・セル間隔・表幅・キャプションの前に区切り線を置き、各見出しを標準ToolsPanelの3点メニュー付きとする。

| 設定 | 契約 |
| --- | --- |
| 先頭行の見出し | オンで対象セルのtag/scopeをth/col、オフでtd/未指定へ1回の更新で置き換える。本文・装飾・範囲外を保つ。見出し行は親管理としてセル側の種類・関連付けを無効にする |
| 列幅 | ToggleGroupControlでequal/auto/customを選ぶ。未指定で列幅もなければequal、保存済み列幅があればcustom。customだけ列番号ラベル付きUnitControlを表示し、空欄の単位は％。他モードへの切り替えでは指定幅を保持して描画には使わない |
| セル間隔 | borderCollapseの既定はcollapse。separate時にRangeControlと単位付き数値欄で横・縦を指定する。連動／個別の表示切り替えだけでは属性を変更しない。異なる値の連動後は混在表示し、次の入力で両軸を変更する。collapseに戻しても値を保持する |
| テーブル幅 | styleTokens.tableWidthで指定し、公開側はfigureへ適用する |
| キャプション | 表の上／下のRichTextでインライン編集し、サイドバーには表示トグル・上下配置・標準AlignmentControlを置く。captionEnabled未指定は本文の有無に従う。非表示で本文を削除しない。空のcaptionは公開しない |

各区分のリセットは現在の属性から純粋関数で計画し、1回のUndoへまとめる。列幅はモードとcolumnsのwidthだけを解除して他の列情報を維持、セル間隔はモードと両軸だけ、表幅はtableWidthだけを解除する。captionは本文を保持して表示オフ・上配置・文字揃え未指定へ戻す。数値の空欄でも解除できる。独立したリセットボタンは置かない。

「スタイル」タブでは、標準の背景色・文字色・タイポグラフィー・外側余白・最小高さを使う。table自体のpaddingや親の「セルのスタイル」パネルは追加しない。セル共通値は一括設定の全セル操作から設定する。

### セル・共通コントロール

- セルの「設定」タブにはToggleGroupControlのTD/TH切り替えとscope、スタイル側には「背景」「位置揃え」「罫線」「サイズ」を配置する。セル単独の切り替えはtagだけを変更し、scopeの保存値は保持する（TDでは出力しない）。親の見出しトグルと一括設定でTDにする場合はscopeも解除する。
- 背景は標準寸法の色見本とテーマパレット・カスタム色・クリアを使う。ColorIndicatorの未設定値は斜線表示とし、色コードの補足、透明／現在の文字色／継承へ戻すの独立ボタンは置かない。保存済みのtransparent/currentColorは保持する。
- テーマの登録済みパレット・サイト設定・ブロック別パレットとカスタム色の許可を尊重し、プリセット参照を保存する。背景色・文字色・罫線と一括設定のパレットは標準コンポーネントで「テーマ」「デフォルト」「カスタム」の順に分類する。空のカテゴリや無効なデフォルトパレットは表示せず、同じプリセットのサイト側の上書きを優先する。由来のない旧設定は一覧表示を維持する。テーマCSSにしかない色をパレットへ自動追加しない。
- 罫線と内側余白は別パネル。標準のborder/dimensionsグループへToolsPanelItemを追加し、BorderBoxControl・SpacingSizesControlを使う。影は追加しない。四辺を指定でき、上／下は中央、左／右は各端へ配置する。単位は入力欄内で変更する。
- 罫線の未指定時の表示・フォールバックはsolid。親の線種を四辺ごとに表示し、表示用の既定値や継承値を保存しない。太さ・色だけの変更で標準UIが返した同じ線種も保存から除き、必要な明示上書きは保持する。
- AlignmentMatrixControlで垂直・水平を同時に指定する。垂直はverticalAlign、水平はstyle.typography.textAlign。再クリック・選択中のEnter／Spaceで両軸を解除する。未指定・混在は未選択表示、垂直の最終フォールバックはtop。標準の水平揃えツールバーは置かず、解除後に旧horizontalAlignが復活しないようにする。
- 説明は削除の影響・操作不可の理由・親管理・結合範囲など判断に必要な場合に絞る。ラベル・アイコン・プレビューから分かる説明を重ねない。操作名・ツールチップ・読み上げ・可視フォーカスは維持する。
- 独自設定欄はコンテナーのgapで項目間を16px、セル間隔の小見出しと入力を8pxに揃え、各コントロールの外側余白を重ねない。標準ToolsPanelの見出しと入力の間隔は維持する。標準の背景色と直後のTH背景色は境界線を1本にまとめ、ストライプ色の独立した枠線は維持する。

## 7. スタイルの保存・継承・出力

標準の色・タイポグラフィーはblock.jsonのサポートと標準属性を正本とする。テーブルとセルの両方で、書体・文字サイズ・行間・太さ・斜体・字間・文字装飾・大文字小文字・文字方向を許可し、テーマの制限を尊重する。水平揃えも標準属性を使うがUIは位置揃えマトリックスが担当する。

セル背景・罫線・余白・表幅・セル間隔はstyleTokensへ保存し、明示された妥当な値だけを出力する。名前・一括値の展開先は`includes/style-tokens.json`をTypeScript/PHPで共有する。カスタムプロパティは各セルの実プロパティから参照し、未指定値をローカルで初期化して上位の継承を遮断しない。

公開tableの標準色・タイポグラフィーはget_block_wrapper_attributesへ委譲する。プリセットは標準クラス、カスタム値は標準宣言とし、同じ宣言を二重出力しない。セルはWordPress Style Engineを使い、水平揃えや6.6で未出力のwriting-mode等だけを許可値で補完する。標準設定を明示したスコープでは対応する旧スタイルトークンをinitialで遮断し、計算済みの文字サイズ等を子へ継承する。

表・セルの既定装飾は共有mixinで編集画面・公開・一括プレビューへ適用する。タグに由来するフォント・背景画像・角丸・影等の差を中立化し、通常のコアテーブルやセル内の子ブロックは一括リセットしない。見出しの既定の太さは700で、親の妥当なfontWeightがあれば描画用data属性で継承へ切り替え、セルの明示値を優先する。判定状態を保存しない。captionの文字・余白も共用する。

公開tableの外枠は既定でborder:none。セルの余白は一般的なテーマの!importantに対処するため、公開側padding宣言だけ!importantを許容する。辺別変数を解決したpadding・border-width/style/colorのショートハンドを使い、太さ・線種・色をまとめるborder指定や、親で組み立てた複合値の継承で辺の解除を壊さない。任意の詳細度のテーマCSSからの完全な隔離は保証しない。

### 背景ルール

親の標準背景色を地色とし、TH用のheaderBackgroundColorとTDのstripeBackgroundColorを重ねる。stripeModeはnone/rows/columnsの排他指定。行はheaderRowsを除いた本文の2・4…行、列は表全体の2・4…列を論理座標で判定する。THはストライプ対象外、結合セルは左上の位置でセル全体を判定する。

背景の優先順位は、セル個別色→見出し／ストライプ色→セル共通色→透明。透明部分からtableの地色が見える。個別transparentはルールを遮断し、クリアはその位置のルールへ戻す。ルールの色を各セルの保存値へ複製しない。

標準背景色と同じInspectorグループへ背景ルールを統合する（6.6はcolor、新しい検証環境はbackground）。ルールだけのリセットはルールの色・モードだけ、同じパネルの全リセットは標準背景色も解除する。最新トークンから変更し、幅・セル間隔等は保持する。独立した色ボタンの四辺の枠を欠落させない。

## 8. セルの一括設定

### 配置・選択・プレビュー

- セッションと環境はTableEditで保持し、設定サイドバーが閉じても草稿を失わない。Modalは左に「セルの選択」・通知・選択数、右に240px基準の1列の設定。最大幅1200px、782px以下は上下配置とする。
- 本文の利用可能な高さを左右に割り当て、表と設定列を独立してスクロールさせる。プレビューの表は領域幅を下限に内容・列幅・セル余白が必要とする幅を確保し、収まらない場合だけプレビュー内で横スクロールする。公開表の横スクロール設定とは独立させ、行列番号の固定表示と選択枠をスクロール位置へ追従させる。選択数は表の外側の下端、通知はその上の高さを制限した領域に置く。モーダル全体の高さをJSで手計算しない。
- 均等幅のプレビューは表示用サンプルの折り返し可能な最小幅と計算済みのセル余白・罫線・結合幅・セル間隔から列の必要幅を測り、全列へ同じ幅を割り当てる。測定用サンプルは高さ0で表示・読み上げの対象外とし、可視ラベルの折り返しは維持する。ResizeObserverで文字・フォント・領域幅の変化へ追従し、測定結果は編集状態だけで保持する。固定レイアウトを維持できる幅をReact経由で指定し、公開用の列幅へ保存しない。
- 設定順は種類・位置揃え・背景・罫線・余白・タイポグラフィー。枠付きで常時表示し、タブ・折りたたみは使わない。閉じる・適用は右列末尾。閉じるは入力が無効な場合も使用可能とする。
- 初期は未選択。左上で全セル、行番号で行、列番号で列へ排他的に切り替える。同じ単位の複数・非連続選択は修飾キーなしでトグルする。選択中の再クリックで解除する。独立した全選択・解除ボタンとセル本体の選択切り替えは置かない。
- 選択は論理行・列の連続範囲ごとの外周枠で示し、隣接範囲の中間線を出さない。全選択時は全行列番号も選択色・aria-pressedにする。標準ボタンのアクセント配色を使う。
- 実tableの現在の行高・列幅をDOMから測定し、ResizeObserverに追従するReactの外側装飾で枠を描く。DOMを直接書き換えない。全列に幅があっても行番号欄を確保し、行番号のクリック領域は行全高とする。
- プレビューは現在の罫線・背景・文字・余白・列幅、テーマのプリセットと草稿を反映する。内容は位置を示すサンプル。表の外側余白・最小高さは持ち込まない。
- 左上に10pxのTH/TD表示を絶対配置し、THは濃い背景に白文字、TDは白背景に濃い文字。寸法・公開出力へ影響させず、aria-describedbyで種別を補足する。草稿で種類が変わった場合は見出し背景と太さも再計算する。

### 草稿・入力・適用

草稿は「項目・対象セル・全体操作か」を持つ順序付きの一時操作としてModal内に保持する。未変更／上書き／継承へ戻す、0／未指定を区別する。選択の切り替え・解除で草稿を破棄せず、項目ごとに後の操作を優先する。再選択では草稿を含む共通値・継承・複数値を表示する。

各パネルは公開のToolsPanel/ToolsPanelItemが生成するToolsPanelHeaderと3点メニューを使う。内部パスから読み込まない。「セルの種類」のリセットは現在範囲の種類の草稿だけを取り消し、他のパネルはその範囲の当該パネル全項目を継承へ戻す。details・設定値一覧・個別リセットは置かない。対応するフォームの混在値はplaceholderの「複数の値」で示し、非対応の標準入力は既存の混在表示を使う。色はパレットでもクリアできる。

タイポグラフィーは文字色・フォントサイズだけを初期表示し、書体・外観・行間・字間・文字装飾・大文字小文字・文字方向は3点メニューから表示を切り替える。標準の入力部品とテーマの許可・候補を使う。非表示で値を初期化しない。全リセットは非表示項目を含む。全項目非表示時は標準メニューの制約で、1項目を再表示してからリセットする。

種類はセルへ保存し、親へ共通化しない。親管理の見出し行は変更対象外、TDにしたセルのscopeは解除する。列幅の草稿・パネル・適用処理は持たず、親のcolumnsとモードを保持する。罫線・余白の標準部品は選択範囲が変わる時だけ再生成し、画面幅や値の編集では再生成しない。

一括処理の失敗は`BulkError`のコードと元の例外を保持し、入力不正・選択不正・構造変更・予期しない例外を区別する。

適用は現在の選択にかかわらず全草稿の影響範囲を1回で反映し、各回を独立したUndo/Redoにする。直前の構造・列設定・見出し境界を再検証し、古い選択なら全適用を拒否する。本文・未変更項目・非対象セルを保持する。

適用後はModal・選択・設定項目の表示を維持し、反映済みの表と環境を新しい基準にして草稿をクリアする。閉じる・×・Escapeは未適用分だけを破棄する。閉じた後は起動ボタンへ、起動ボタンがなくなった場合は親テーブルへフォーカスを戻す。

### 結合セルと部分選択

選択を結合形状へ拡張しない。背景・タイポグラフィー・位置揃え・セル種類は一部でも交差するセル全体へ適用する。罫線・余白は実在する辺の全長が選択内にある場合だけ変更する。

列選択の左／右辺はその端の列が選択されていること、上／下辺は占有する全列が選択されていることを条件とする。行選択は縦横を入れ替える。非連続範囲の隙間を変更しない。同じ判定を共通値表示・上書き・解除・草稿取り消しへ適用し、変更できない項目を示す。セル途中の罫線や余白は生成しない。

### 共通値と個別値の正規化

1. 全セル操作は変更した項目だけを親の共通値へ反映し、その項目のセル上書きを解除する。全行・全列が論理グリッドを覆う場合も全体操作とする。
2. 部分操作をセルへ仮反映し、適用時点の全セルについて、変更項目だけ保存値と継承を比較する。
3. 全セルで同値になった項目は親へ集約し、セル側の同じ項目を解除する。
4. 混在する項目も、適用時点の親共通値（今回の草稿を含む）と同じセル個別値を、非選択セルも含めて解除して継承を優先する。異なる値を残し、親が既に同値ならプリセット等の保存形式を保って書き直さない。
5. 1emと16px、プリセットと固定値は別物として比較する。未変更項目・計算済みCSS・テーマの見た目で共通化しない。行別の保存先を追加しない。

背景だけは位置別の見出し／ストライプの継承先を評価し、個別指定を消して同じ表示を維持できる場合だけ解除する。全セル色指定でもルールを削除せず、ルールを超えるために必要な個別色を保持する。全セルクリアは親共通色と個別色を解除し、ルールへ戻す。

プレビューと適用は同じ純粋な計画を使い、全体操作で解除された旧値が環境キャプチャから復活しないよう変更項目だけ環境へ戻して投影する。後から追加したセルはその時点の親共通値を継承し、部分行列の設定を別途保存して将来のセルへ適用しない。

## 9. クリップボード・CSV取り込み

### 入力と起点

作成画面・table/cellツールバーから専用Modalを開く。ファイル読み込み・アップロードは実装しない。通常のRichText内の貼り付けは変更しない。

HTML表、TSV、CSV（カンマ／セミコロン）を自動判定し、手動の形式選択も許可する。CSV/TSVは引用符内の区切り・改行・二重引用符を扱い、先頭ゼロ・大きい数値・日付・式・空白を文字列のまま保持する。型推論・式の実行は行わない。末尾の改行だけで余分な行を増やさず、意図した空行は残す。

新規表または指定起点からの上書きを選ぶ。tableからは(0,0)、cellからはそのセルの左上を初期起点とし、既存セルのプレビューで変更できる。結合セルのクリックはその起点を選ぶ。既存表全体の置換・残りセルの削除は行わない。完成済み表からの新規取り込みはその表の直後へ挿入し、未作成表ではその場所に作成する。

### 解析と反映

- 一時データはImportData（行列数・座標・span・文字・種類・欠損・形式）。解析、純粋なplanImport、ストア検証、実体化・適用を分け、保存用の二次元配列を追加しない。
- HTMLはparse5の不活性な構文木で読み、1つの表から文字・TH/thead・妥当な結合だけを抽出する。スクリプト・スタイル・外部リソースを実行／挿入しない。装飾・画像・caption・列幅は取り込まず、複数表・入れ子表を拒否する。
- rowspan/colspanは正の整数。前後空白・先頭ゼロは正規化し、0・不正値・範囲外・重複・見出し境界や行グループをまたぐ結合を拒否する。tfootは本文の後へ並べて本文として扱う。
- 明示的な空欄は内容を消去する。短い行の欠けた項目は警告し、その位置の既存内容を保持する。新規表の欠損位置は空セルで埋める。
- 対象の内容はセルテキスト1つへ置き換える。元の画像や、既存データに残るグループ等も削除対象。文字を安全なRichText値へエンコードして改行をbrへ変換し、入力HTMLを本文へそのまま使わない。
- 上書きでは対象の種類・scope・装飾・結合、親の設定・caption・背景ルール・既存列のモードとメタデータ、範囲外の内容・IDを保持する。既存の不正なセルブロックは、保存時に元のHTMLへ戻ることを避けるため、復旧まで対象への上書きを拒否する。
- 必要な行列だけ末尾へ追加する。新しい列は空の設定、セルは親を継承する。既存座標をずらさない。新規表は元のID・アンカー・装飾・caption等をコピーしない。
- 新規CSV/TSVの先頭行をTHにする設定は既定オフ。新規HTMLはTHとtheadを採用し、既存表への上書きは既存のセル種類を保持する。
- 単一1×1値は既存結合セルの内容だけを変更できる。複数値では入力と既存結合の形状が完全一致することが必要。欠損位置を含む長方形と既存結合の交差も検証し、途中交差・不一致を拒否する。既存表の追加領域へ新たな結合は作らず、新規表としての取り込みを案内する。

### プレビュー・安全性・上限

入力→実データのプレビュー→承認と確定の順。起点プレビューは既存の入れ子グループ等からも文字を抽出し、実際の子ブロックを実行・描画しない。追加領域と変更位置、起点と拡張後の寸法を示す。必要なら確定ボタンに拡張後のサイズを表示する。

内容がある対象は件数と置換の影響を示し、明示承認を得る。セル・子ブロック・表・祖先テンプレートのユーザーロック、編集モード、挿入・削除の許可を尊重する。結合操作のロック例外を使わない。構造保護用のtable内部の固定は、保持するセルを削除する許可と混同しない。

新規表を元表の隣へ挿入する場合は挿入先の制約を検証する。元表を変更しないため、元表の削除ロックだけを理由に新規表の作成を禁止しない。

開いた時点の表と確定時点の表を照合し、内容・属性・構造・ロックが古い確認で適用しない。全体を検証してから1回で反映し、1回のUndo/Redoで拡張と内容を戻す。キャンセルは無変更。セッションはTableEditで保持し、幅変更で失わない。画面と解析はローカルの遅延ロード用JSへ分離し、通常の初期読み込みに解析ライブラリを含めない。

上限は100行・50列・5,000論理セル、元入力1,000,000・本文200,000のJavaScript文字列長。超過時は切り捨てず拒否する。上書きの拡張後のサイズも上限内とする。手動初期作成の1〜20制限を取り込みのために広げない。

## 10. 互換性・検証契約・未確認事項

- WordPress 6.6と設定済みの新しい環境で、挿入・入れ子編集・リストビュー・ツールバー・キーボード・Undo/Redo・保存再読み込み・コピー＆ペースト・複数表を検証する。構造・値検証は純粋関数の単体テスト、公開描画はPHP検証、実DOM・UI・アクセシビリティはE2Eが担当する。
- 構造の単体テストは占有・欠損・重複・不正値・結合・解除・行列操作・元データの非破壊を含める。スタイルはサイト／表／セルの継承・解除・共通化、PHP/TypeScriptの同一JSON事例を含める。取り込みは形式・引用・欠損・上限・結合・ロック・鮮度・不変性を含める。
- 公開table/thead/tbody/tr/th/tdの間に編集ラッパーを混入させない。狭い画面、可視フォーカス、操作名、見出し・scope、操作UIの配色、コンソール・ブロック検証エラーも確認する。実行コマンドと環境は開発手順を参照する。
- 最低対応版の実験的コンポーネントはstyle-compatへ限定する。連続適用のUndo分離に使う`__unstableMarkLastChangeAsPersistent`と、候補制限の`blockEditor.__unstableCanInsertBlockType`も互換境界へ閉じ込め、両環境の回帰検証を維持する。内部ファイルパスからの読み込みは行わない。
- 編集Grid・公開table・サンプルの一括プレビューは、列幅計算・共有罫線の競合・表示幅による可変文字サイズ・任意のテーマCSSまで完全一致しない。未解決の差を隠さない。
- 一括設定を開いたまま狭い画面へリサイズした後、行列番号へのフォーカス移動でモーダルの見出しが画面外へ動く場合がある。横スクロール・選択・選択枠の追従は確認済みだが、この表示位置の変化は未解決とする。
- 独自Registryの外部エディター、スクリーンリーダー実機・ドラッグ操作の網羅的検証、Excel／Googleスプレッドシート実機からのコピーは未確認。ブラウザーの通常テキストクリップボードと合成HTML/TSVのMIME検証を区別する。
- WordPress 6.6の投稿者権限では、標準段落の数値文字参照が保存時に正規化されることがある。セルテキストの保護を維持し、段落変換後の本体の挙動を保証しない。
- WordPress 6.6の位置揃えツールチップの重なり、リストビューから段落へ戻る際の親セルへのフォーカスに注意し、本文への実入力まで確認する。
- 全タイポグラフィー項目を非表示にした場合の標準Reset allの制約や、標準メニューの文言と草稿保持の差は互換層・操作説明・回帰テストで明示する。
